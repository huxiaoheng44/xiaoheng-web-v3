PingPong Vision – camera-based HMI visibility

PingPong Vision reads production-machine HMI screens with a camera and AI OCR, then turns the readings into live dashboard data.

Problem: machine data is trapped behind HMI screens

Older machines and vendor-controlled platforms may not expose PLC/API data. The visible screen is often the only universal interface.

01No PLC integration

The system avoids control commands, OPC UA tags and machine automation logic.

02Works across brands

A camera can observe Siemens, Multivac, legacy panels and analog-like interfaces.

03Creates history

Visible values become structured readings, events and dashboard trends.

Core workflow: one camera turns screens into data

The operator configures the HMI once, then the worker repeatedly reads the configured fields from live frames.

  1. 01 Capture HMI – a USB camera streams the machine screen locally or through the relay
  2. →
  3. 02 Calibrate fields – onboarding stores screen corners and field bounding boxes
  4. →
  5. 03 Read + persist – the worker applies perspective correction, calls Gemini OCR and saves readings

Architecture

Each service owns one part of the vision pipeline

ServiceResponsibility
camera-serverRuns on the camera PC; exposes LAN MJPEG or pushes frames to the relay.
relay-serverBuffers the latest frame per camera and fans out MJPEG to the frontend and worker.
hmi-data-serverBusiness REST API; owns HMI pages, fields, readings, events and monitor jobs.
hmi-monitor-workerA single process that actually runs the OCR loops and writes readings.
TimescaleDBStores HMI pages, field definitions, time-series readings, events and worker status.

Data model: HMI data lives in the backend

The browser owns only temporary session state. HMI business data is loaded from and written to the HMI data server.

TableContent
hmi_pagesConfigured camera/HMI page or machine location.
hmi_fieldsDetected labels, units, visual types and bbox_percent.
hmi_readingsTime-series OCR values, confidence, latency, metadata.
hmi_eventsImage-change, operational and field-threshold incidents.
hmi_monitor_jobsDesired monitor state plus worker heartbeat/status.

Events and reliability: monitoring is more than OCR values

01Image-change AI

Compares baseline and live frames to detect hands, a moved camera, page changes or value changes.

02Operational events

The worker records camera_connection_lost and repeated_unreadable_values.

03Field thresholds

Dashboard rules turn readings into warnings and alerts.

Known constraint: calibration depends on camera alignment and HMI page stability. If the camera moves or the screen layout changes, the stored field boxes can stop matching the live image.

Takeaway

PingPong Vision reads the machine screen, not the machine controller. The project demonstrates a non-invasive path to production visibility: camera capture, AI OCR, time-series storage, event logging, and a dashboard for HMI-based machine monitoring.
