Web Harvest RAG

A config-driven RAG chatbot starter – scrape any site or PDF, chunk and embed it, retrieve with hybrid vector + keyword search, and chat over it. Built, benchmarked against a public IR baseline, and deployed to production.

Architecture: Scrape → Chunk → Embed → Retrieve → Chat

Six stages, each independently swappable – the retrieval stage is where most of the engineering work actually happened.

1Scrape

config/sources.json → scraper.py pulls HTML pages and PDFs and extracts clean readable content.

2Chunk

Fixed-size token windows or structural (heading-aware) splitting – compared systematically, not assumed.

3Embed

OpenAI text-embedding-3-small, cached by content hash so re-runs don’t re-pay the API.

4Retrieve

Vector (FAISS / Supabase pgvector) + BM25, fused.

5Generate

The FastAPI backend builds context from retrieved chunks, calls the chat model and stores the conversation.

6Chat

Next.js UI – add sources, watch the index build live, ask questions, see cited sources.

Production uses Supabase pgvector for retrieval. A separate, standalone module – retrieval_lab – exists purely to answer “is this actually the best way to do stage 4?” without touching the live app.

retrieval_lab: a standalone experimentation harness

Questions about retrieval quality, each answered with real numbers instead of assumptions – kept fully separate from the production app.

1Chunking strategies

Fixed-size token windows vs. structural (heading-aware) splitting, compared head to head.

2Vector vs. BM25 vs. Hybrid

FAISS cosine search, rank_bm25 keyword search, and two fusion strategies (linear + RRF).

3Cross-encoder rerank

ms-marco-MiniLM reranking the hybrid candidate pool – tested, not assumed to help.

4Chunk-size sweep

200 / 500 / 1,000-token chunks, measuring the completeness-vs-noise trade-off directly.

5LLM query rewriting

Paraphrase each query into variants, retrieve for each, merge via reciprocal rank fusion.

6Error-bucket analysis

Every imperfect-recall query auto-sorted into a failure category, then read through by hand.

7Alpha tuning

Hybrid fusion weight swept on a held-out validation split, evaluated on a separate test split.

8LLM-as-judge answer eval

Not just “was the right chunk retrieved” – is the generated answer actually faithful to it?

Five real bugs, found by actually testing

Every one of these was caught by running the system end to end and looking hard at the output – not by code review alone.

Security

Unauthenticated secrets endpoint

The in-app settings panel let anyone GET the real OpenAI/Supabase keys in plain JSON with zero auth. Disabled in production before the first public deploy.

Correctness

Zero-fill scoring bug in hybrid fusion

Candidates outside one method’s top-20 were scored 0 instead of their real value – unfairly penalizing chunks only one method liked. Fixed with exact re-scoring over the full candidate union.

Reproducibility

Non-deterministic recall@k

The same query, index and alpha produced three different recall@1 scores across three runs – a bare Python set()’s hash-seed-dependent iteration order was silently reshuffling score ties.

Eval calibration

LLM judge conflated two failure modes

A correct “I can’t confirm this” refusal was scored as harshly as a hallucination. Average score jumped 3.32 → 4.92 / 5 once the judge prompt separated retrieval failure from generation failure.

Production

Dependency drift broke the live chat

An unpinned supabase client picked up a newer API where .insert().select().single() no longer exists – every /chat call returned 500. Found by smoke-testing the fresh deploy, not by CI.

Findings: what actually won, and where

MULTIVAC – structural-500

recall@k, 30 hand-labeled queries

MethodRecall@1Recall@5
Vector only60.0 %93.3 %
BM25 only75.0 %95.0 %
Hybrid (linear)78.3 %96.7 %

NFCorpus – fixed-500 (BEIR)

recall@k, 323 official test queries, tuned α = 0.8

MethodRecall@5Recall@100
Vector only13.9 %35.4 %
BM25 only11.6 %23.0 %
Hybrid (linear)14.4 %36.0 %

BM25 wins on MULTIVAC – brand-heavy content (“MLC”, “PEAQ”, “GS1 Digital Link”) rewards exact keyword match. Vector wins on NFCorpus – technical medical abstracts vs. colloquial queries create a vocabulary gap that only semantic search bridges. Hybrid beats the better of the two on both corpora, but only once tuned per corpus. Neither method is a safe default.

Validation: this harness’s BM25 recall@100 on NFCorpus (23.0 %) lands within 2 points of BEIR’s published official BM25 baseline (25.0 %) – the low absolute numbers are a property of the dataset, not a bug in the implementation.
